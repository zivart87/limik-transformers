### Новая линейка продуктов

1. **Power Transformers** — Generator Step-Up (34.5–500kV, до 500MVA), Substation (34.5–500kV, до 500MVA), Auto Transformers (34.5–500kV, до 500MVA)
2. **Distribution Transformers** — Pad-Mounted (до 34.5kV, до 10MVA), Dry-Type (до 34.5kV, до 30MVA), Substation Distribution (до 34.5kV, до 20MVA)
3. **Special Purpose Transformers** — Inverter Duty (12.4–34.5kV, до 10MVA), Station Service (2.4–34.5kV, до 20MVA), Furnace (12.4–46kV, до 50MVA), Grounding (12.4–34.5kV, до 69kV/20kAmps), Mobile (до 230kV, до 100MVA)

### Решения по структуре продуктовых страниц

Референс: [ayr.energy](https://www.ayr.energy/) — их Products-меню (Power/Distribution/Special Purpose Transformers, HV Circuit Breakers, MV Switchgear) почти 1:1 совпадает с новой линейкой. Проверено на `/products/power-transformers`: **подтипы внутри категории НЕ имеют отдельных URL** — это карточки на одной странице категории (полный шаблон: hero, Why Us, сертификаты, testimonials, FAQ, форма — один на категорию).

**Правило для LIMIK:** одна страница = одна категория, подтипы — карточки внутри неё, кроме явного исключения ниже.

Категории и статус:

- **Power Transformers** — одна страница, GSU + Substation + Auto как карточки. Объединяет 2 текущие отдельные страницы (`/transformers/autotransformers/`, `/transformers/gsu/`) в карточки внутри новой единой страницы.
- **Special Purpose Transformers** — одна страница, 4 карточки (Inverter Duty, Station Service, Furnace, Grounding). Mobile сюда **не входит**.
- **Mobile Transformers — исключение, остаётся отдельной полноценной страницей** (решение пользователя 2026-08-25: продукт достаточно значим для бизнеса, чтобы не понижать до карточки — сохраняет текущий полный шаблон с FAQ/compare-table/CTA-логикой).

**Не забыть при реализации:** старые URL `/transformers/power/`, `/transformers/autotransformers/`, `/transformers/gsu/` уже проиндексированы и накопили SEO/GEO-работу (structured data, FAQ, compare-table) — при переезде на новую структуру обязателен план 301-редиректов на новые адреса, а не просто удаление старых страниц.

## Миграция на Next.js (v2 — главный проект)

**Зачем:** 100+ страниц на статическом HTML = кошмар поддержки.
Изменить nav = редактировать 100 файлов. На Next.js = 1 файл.

**Что даёт Next.js:**
- Компоненты: Nav, Footer, Layout — один файл, везде применяется
- Блог через MDX/Markdown (без кода добавлять посты)
- Позже: личный кабинет клиента, отслеживание производства
- SEO из коробки
- Работает на Vercel без изменений в деплое

### Риски миграции (зафиксировано 2026-08-08)

Пока Next.js-проект строится **рядом** с текущим сайтом (отдельный Vercel-проект/preview-домен, без изменений в проде) — риск для текущего трафика/статистики нулевой. Все риски возникают **только в момент переключения домена** (Этап 4):

| Риск | В чём дело | Как избежать |
|---|---|---|
| Потеря позиций/трафика | Смена URL-структуры (даже мелочь вроде slash в конце) — для Google это новая страница | Таблица «старый URL → новый URL», 301-редирект на КАЖДЫЙ, даже если путь не менялся |
| История в Search Console | Метрики по конкретному URL не переносятся при смене URL (агрегированная история домена — сохраняется) | Сохранять URL-пути 1-в-1 |
| Разрыв в GA4/GTM | Тот же контейнер GTM, встроенный корректно — трекинг не прерывается | Проверить, что все события (submit формы, клики CTA) фактически стреляют на новой версии — ДО переключения, не после |
| Временная просадка позиций | Google переобходит и переоценивает сайт после любой крупной миграции — нормально, недели | Не запускать переключение перед важной рекламной кампанией/сезонным пиком |
| Битые ссылки | Внешние ссылки/закладки на старые URL, которых нет в новой версии | Полный аудит существующих URL перед переключением |
| Sitemap/robots.txt | Должны продолжать отдавать те же адреса | Next.js умеет их генерировать — сверить с текущими перед запуском |

Хостинг не проблема — Vercel уже используется, Next.js разворачивается там нативно без смены инфраструктуры.

**Не путать с фиксами на текущем статическом сайте:** SEO/GEO-правки (schema, contrast, internal linking и т.п.) делаются на v1 прямо сейчас и не блокируются миграцией — просто переедут вместе с контентом, когда придёт время Этапа 4.
