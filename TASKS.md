## Миграция на Next.js (v2 — главный проект)

**Зачем:** 100+ страниц на статическом HTML = кошмар поддержки.
Изменить nav = редактировать 100 файлов. На Next.js = 1 файл.

**Что даёт Next.js:**
- Компоненты: Nav, Footer, Layout — один файл, везде применяется
- Блог через MDX/Markdown (без кода добавлять посты)
- Позже: личный кабинет клиента, отслеживание производства
- SEO из коробки
- Работает на Vercel без изменений в деплое

### Этапы миграции

**Этап 1 — Подготовка (1 неделя)**
- [ ] Создать Next.js проект рядом с текущим
- [ ] Перенести дизайн-систему (limik.css → globals.css)

- [ ] Перенести главную страницу

## Будущее (v3 — личный кабинет)

**Срок:** через ~2 года

**Концепция:**
- Клиент заказывает трансформатор → получает доступ в личный кабинет
- На производстве рабочие сканируют QR-коды на каждом этапе
- Данные автоматически попадают на сайт
- Клиент видит: Проектирование → Сборка → Тестирование → Отгрузка

**Технически:** Next.js + база данных (Supabase или Vercel Postgres) + API для QR

## Технические задачи — SEO, аналитика, безопасность форм

### 🔴 Высокий приоритет (делать скоро)

- [ ] **GA4 через GTM** — Google Analytics 4. GTM установлен но пустой. Без GA4 нет данных кто и откуда приходит
- [x] **Sitemap.xml + robots.txt** — готово. Все индексируемые страницы в sitemap (включая 5 industries), noindex-страницы (privacy-policy, disclaimer, thank-you) из sitemap убраны, robots.txt ссылается на sitemap
- [ ] **SPF / DKIM / DMARC записи на домене** — без них письма из GHL попадают в спам клиентов. Настраивается в DNS домена

### 🟡 Средний приоритет

- [ ] **Спам-защита форм (honeypot-поле)** — после запуска рекламы боты начнут засорять GHL. Honeypot — скрытое поле, боты его заполняют, мы отсекаем
- [ ] **Авто-письмо после формы** — клиент отправил заявку, должен получить письмо "получили, ответим в течение 24ч". Настраивается в GHL workflow, не в коде
- [ ] **Microsoft Clarity** — бесплатный инструмент. Записывает сессии пользователей, показывает тепловые карты. Видишь где люди застревают и уходят
- [ ] **Open Graph мета-теги** — когда ссылку кидают в LinkedIn или мессенджер, должна появляться красивая карточка с фото и описанием. Сейчас ничего нет
- [ ] **Сократить длинные meta description (копирайтинг)** — у 8 страниц описание длиннее рекомендуемых ~155–160 символов, Google обрежет их в выдаче: `company/` (180), `industries/data-centers/` (195), `industries/defense/` (176), `industries/epc-contractors/` (173), `industries/renewables/` (175), `industries/utilities/` (181), `transformers/power/` (173), `transformers/mobile/` (174). Нужен копирайтинг-проход, не техническая правка — сократить смысл, не потеряв ключевые слова

### 🟢 Позже

- [ ] **Schema markup (структурированные данные)** — Organization, Product схемы для Google. Даёт расширенные сниппеты в поиске
- [ ] **Cookie Consent баннер** — GTM и GA запускаются без согласия. По GDPR/CCPA нужен баннер. Актуально при работе с европейскими клиентами
- [ ] **Валидация форм с понятными ошибками** — сейчас если ввести неверный телефон форма молча не отправляется
- [ ] **Live Chat виджет** — GHL скорее всего включает чат-виджет. Для B2B с длинным циклом продаж важно
- [ ] **Core Web Vitals аудит** — LCP, CLS, INP метрики. Конкуренты GE/Siemens мобайл 35/100 — у LIMIK шанс доминировать в поиске за счёт скорости
