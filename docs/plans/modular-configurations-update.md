# Modular: план уточнення конфігурацій

Оновлено 2026-09-30 після аналізу CANCOM. Користувач погодив напрям і попросив оновити план. Реалізацію на сторінці ще не виконано.

## Контекст і порядок погодження

Уточнення користувача 2026-09-30: готового продукту LIMIK Core ще немає. Сторінка потрібна для перевірки попиту на нішу; лінійка формується як концепція на основі правдоподібних ринкових орієнтирів. Параметри й тексти погоджуємо з користувачем. Агент готує технічно послідовну пропозицію та пояснює компроміси простою мовою; не перекладає вибір характеристик на користувача без рекомендації.

Погодження концепції не означає завершене інженерне проєктування. Наявність продукту, випробувань, сертифікацій, готових поставок чи кейсів не стверджуємо за аналогією з конкурентами. Майбутню комплектацію описуємо як плановану; попередній статус має бути зрозумілий читачу, а не лише позначений прихованим HTML-атрибутом.

## Погоджений напрям

Три варіанти за масштабом розгортання:

| Назва | Роль у лінійці |
|---|---|
| Core 20 | Компактний модуль для невеликого розгортання з наявним живленням майданчика |
| Core 40 | Основний AI-модуль із комплектацією живлення й охолодження під проєкт |
| Core Campus | Індивідуальне рішення з кількох модулів; назву зберігаємо, але не подаємо як стандартну модель з фіксованими параметрами |

Охолодження, UPS, генератор і трансформатор описуємо як параметри комплектації. Включення трансформатора в Core 40 та склад Campus потрібно підтвердити; рішення про структуру не є підтвердженням інженерних характеристик. Не обіцяємо автоматичну сумісність або модернізацію Core 20 до Core 40.

Поточні кольори, розгортання, затримку появи контенту, hover і відкриття по картці зберігаємо. Характеристики CANCOM не переносимо до LIMIK.

## Порядок робіт

### 1. Побудувати та погодити матрицю концепції

Дослідницька частина підготовлена 2026-09-30: [одна рекомендована матриця](../research/limik-core-concept-matrix-2026-09-30.md). Пропозиція: Core 20 — 100 kW / 2 стійки; Core 40 — 600 kW / 6 IT-стійок; Campus — від двох Core 40 за індивідуальним проєктом. Спеціальний ширший корпус, зовнішні технічні блоки та плановий горизонт першої лінійки 6–9 місяців також потребують погодження. Числа не затверджені, чекліст погодження не закритий, HTML не змінено. Наступний крок — погодження цієї конкретної пропозиції користувачем.

- [ ] Агент пропонує по одній базовій комплектації Core 20 і Core 40 та правило формування Campus, спираючись на первинні джерела виробників із дослідження конкурентів.
- [ ] Для кожної комплектації розділити IT load і загальне споживання майданчика; перевірити кількість стійок × навантаження, охолодження, запас живлення, трансформатор і резервування. Максимальна щільність окремої стійки не означає таку щільність усіх стійок одночасно.
- [ ] Вказати, що розміщено всередині контейнера, а що зовні: трансформатор, тепловідведення, генератор тощо. Ринковий діапазон сам по собі не доводить, що все вміщується у заданий контейнер.
- [ ] Розмежувати трансформатор, UPS, генератор, сервери/GPU: планується в базі, опція або обладнання замовника.
- [ ] Для Campus показати принцип збільшення кількості модулів; не приписувати йому довільний стандартний трансформатор чи фіксовану потужність.
- [ ] Запропонувати обережні планові строки з поясненням початкової та кінцевої події; не обіцяти гарантовану дату поставки неіснуючого продукту.
- [ ] Представити користувачу одну рекомендовану матрицю, коротко пояснити підстави та невизначеності й отримати погодження перед перенесенням параметрів у сторінку.

Результат: узгоджена з користувачем концепція лінійки, джерела орієнтирів і список питань, які залишаться для майбутнього інженерного опрацювання. Сертифікації, гарантії та SLA не вигадуємо.

### 2. Підготувати узгоджені тексти

2026-09-30 користувач доручив рухатися далі після пояснення наступного кроку. Підготовлено [пакет текстів для погодження](../page-drafts/limik-core-configurations-copy-2026-09-30.md): картки, порівняння, комплектація, CTA та пов'язані формулювання Hero/Platform/Specifications/Timeline/FAQ. Погоджений візуальний орієнтир — CANCOM NON ISO, зі збереженням кольорів і анімації LIMIK. Числову матрицю не вважаємо автоматично погодженою: 100/600 kW представлено разом із текстами як попередній цілісний пакет. Для публічного строку рекомендовано «за проєктом»; 6–9 місяців залишаються внутрішнім припущенням. HTML не змінено. Наступна дія — погодження контенту, потім реалізація.

- [ ] Написати для кожної картки сценарій, відмінність і змістовний розгорнутий опис без повторів.
- [ ] У Campus пояснити індивідуальне компонування та масштабування; не подавати 10 MW+ як фіксовану комплектацію.
- [ ] Уточнити Hero: власний трансформатор не входить автоматично до кожного варіанта.
- [ ] Звірити згадки моделей у Platform, Specifications, Timeline і FAQ, включно з відповідними відповідями JSON-LD.
- [ ] Зберегти передачу вибраної моделі у форму. Уточнити CTA як запит на конфігурацію, без враження автоматичного розрахунку.

Результат: одна послідовна логіка продукту на всій сторінці. Працювати спочатку над текстами, без нового дизайну.

### 3. Доповнити блок вибору

- [ ] Підготувати різне зображення для Core 20, Core 40 і Campus: спочатку перевірити наявні assets та права використання.
- [ ] Додати компактне порівняння за однаковими критеріями. Для Campus — залежні від проєкту значення там, де немає стандартного параметра.
- [ ] Додати «Included / Optional / By customer» і вимоги до майданчика на основі підтвердженої комплектації.

Результат: можна порівняти варіанти та зрозуміти межі поставки. Геометрію блока уточнювати лише за потребою контенту; погоджену анімацію не змінювати.

### 4. Перевірити та зберегти реалізацію

- [ ] Перед змінами зберегти актуальний стан заторкнутих файлів; попередній архів `_archive/modular-configurations-before-20260930/` не перезаписувати.
- [ ] Звірити тексти й характеристики в усіх згадках та структурованих даних.
- [ ] Перевірити відкриття по картці, кнопку та передачу вибору у форму.
- [ ] Після зміни геометрії перевірити відповідні desktop, проміжну й мобільну ширини та довгий реальний контент; браузер користувача залишити відкритим, власні перевірки робити в окремій вкладці, viewport повернути до 1340×900.
- [ ] Оновити тематичні правила та зробити окремий локальний коміт. Публікація окремо.

### 5. Окремі наступні задачі перед публікацією

- [ ] Замінити медіазаглушки поза Configurations: схема системи, майданчик, виробництво та FAT.
- [ ] Підготувати власний актуальний datasheet після підтвердження параметрів.
- [ ] Підключити реальне надсилання форми; зараз submit лише показує подяку.

Ці задачі не включати непомітно в першу правку текстів конфігурацій. Не змінювати nav/footer, noindex, sitemap або статус публікації.
