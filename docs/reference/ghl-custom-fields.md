# Поля для настройки в GHL

Сайт передаёт данные через вебхук `J26g7N7tbNqN9LDOAD1K` при отправке любой формы.
Ниже — все поля по каждой форме, в том порядке, в котором они реально уходят.

`firstName`, `lastName`, `companyName`, `email`, `phone` — стандартные поля контакта в GHL, маппятся сами.
Всё остальное нужно создать как **Custom Fields** и связать в workflow вебхука с названием поля из колонки "Поле в запросе".

## О полях `first_*` (пункты 27–34 / 16–23)

Отдельно от `utm_*`/`gclid`/`ga_client_id` выше (которые всегда отражают **текущую** заявку), сайт дополнительно передаёт **first-touch**-версии тех же меток — значение самого первого визита с рекламы, зафиксированное в браузере пользователя и хранящееся 90 дней (после — фиксируется заново при следующем визите с UTM/gclid).

Логика: `utm_source` и `first_utm_source` могут отличаться, если человек кликнул по одному объявлению, а заявку отправил через несколько дней уже после клика по другому объявлению (или зашёл напрямую) — `utm_source` покажет последний источник, `first_utm_source` — самый первый.

Важно: поля `utm_*`/`gclid`/`fbclid`/`ga_client_id`/`first_*` приходят в запросе **только если** для них есть значение. Если человек всегда заходил напрямую — этих полей не будет вообще.

---

## Что нужно сделать в GHL

1. Создать кастомные поля контакта под все пункты из колонки "Поле в запросе" (кроме `firstName`, `lastName`, `companyName`, `email`, `phone` — они стандартные).
2. Поля с одинаковым названием (`message`, `formSource`, `pageUrl`, `utm_*`, `gclid`, `fbclid`, `ga_client_id`, `first_*`) — общие для обеих форм, создавать один раз.
3. В workflow вебхука замаппить каждое поле из тела запроса на созданное кастомное поле контакта — источником должно быть **точное имя поля** из колонки "Поле в запросе" (например `gclid`, а не `google_click_id`).
4. Поле `ga_client_id` — уже настроено и проверено (2026-07-03).
5. Поля `first_*` (пункты 27–34 / 16–23) — новые, нужно создать и замаппить. **Обязательно проверить в workflow, что маппинг first_-полей не перезаписывает существующие данные контакта** — если у контакта уже есть значение в `first_gclid` от прошлой заявки, повторная заявка не должна его стирать (сайт со своей стороны это уже гарантирует — присылает первое значение за 90 дней, а не текущее).

## Тест 2026-07-04 — реальные имена полей в GHL

Прогнали тестовую заявку через `/request-quote/` и сверили с тем, что легло в контакт в GHL:

- **`gclid` — зарезервированное системное имя в GHL**, создать кастомное поле с таким именем нельзя. Надежда создала поле **`google_click_id`** и замаппила туда значение из `gclid` тела запроса — это сработало, значение приходит верно. Дальше в документации ориентируемся на `google_click_id` как реальное имя поля в GHL (не `gclid`).
- **`fbclid` (поле для текущего визита) — не замаппилось**, пришло пустым, хотя в теле запроса значение было. Похоже на ту же причину, что и с `gclid` — `fbclid`, вероятно, тоже зарезервированное системное имя в GHL (заполняется из собственного пикселя GHL при реальном клике по рекламе, а не из вебхука). **Нужно сделать то же самое, что и с gclid**: создать кастомное поле под другим именем (например `facebook_click_id`) и замаппить туда значение из `fbclid` тела запроса.
- **`first_gclid` и `first_fbclid` — оба замаппились и пришли верно**, без переименования. Судя по всему, префикс `first_` не конфликтует с системными именами GHL.

**Итог:** поля `gclid` и `fbclid` в колонках "Поле в запросе" выше — это имя в JSON, а не обязательно имя поля в GHL. Реальные имена кастомных полей в GHL:
- `gclid` (текущий визит) → поле в GHL называется **`google_click_id`**
- `fbclid` (текущий визит) → нужно создать под именем **`facebook_click_id`** (или похожим, лишь бы не конфликтовало с системным)
- `first_gclid`, `first_fbclid` → создаются как есть, конфликта нет
