# Організація репозиторію

- Корінь: сторінка входу, робочі конфігурації, AGENTS.md, CLAUDE.md, TASKS.md і загальні HTML-фрагменти.
- assets/images та assets/video: лише файли, потрібні сайту.
- docs/rules: чинні тематичні правила; history — незмінні попередні версії, не інструкції для поточної роботи.
- docs/page-drafts: чернетки сторінок; industries — тексти ніш.
- docs/plans: маркетингові/SEO-плани; docs/reference: довідкові матеріали; docs/reports: аудити та карта перенесень.
- docs/handoff: отриманий дизайн-пакет, зберігається локально до окремого рішення про додавання в Git.
- _archive: локальні скриншоти, ZIP та вихідні медіа. Ігнорується Git; без видалення оригіналів.
- Перед перенесенням перевіряти посилання у HTML/CSS/JS та документах; після — хеші й карту перенесення.
- Не переміщувати production assets лише через формат чи старе ім'я. Не перезаписувати файли призначення.
- Не комітити сторонні зміни разом з організаційними. Карта перенесень: docs/reports/reorganization-2026-09-25.json.

## Публікація та приватність

.gitignore керує тільки новими файлами в Git, не видаляє вже відстежувані файли й не є контролем доступу до сайту.
Ігнорований локальний _archive не потрапляє в Git-деплой, доки його не додано примусово.
Назва docs або _archive сама по собі не захищає URL. Відстежувані документи можуть потрапляти в статичну публікацію.
Не зберігати тут секрети. Відокремлення публічного каталогу від службових документів належить до відкладеної задачі процесу публікації; поточною реорганізацією воно не реалізоване.
Не використовувати .vercelignore як доказ виключення файлів з Git-деплою. Перед зміною Vercel перевірити фактичний спосіб розгортання.
