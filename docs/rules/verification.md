# Перевірки

**Рішення користувача 2026-10-02:** дрібні правки виконувати швидко, без браузерного прогону, скриншотів, адаптивної матриці й субагентів. Агент переглядає diff і за потреби перевіряє синтаксис JS, комітить та робить погоджений push. Вигляд і поведінку користувач перевіряє сам; додаткові перевірки агента — за прямим запитом або після повідомлення про проблему.

До дрібних правок належать зміна тексту, кольору, відступу, порядку елементів і простої анімації наявного блока. Наведені нижче розширені перевірки потрібні для значних змін або окремо запитаної перевірки; не застосовувати їх автоматично до кожної дрібної правки.

| Зміна | Достатня перевірка |
|---|---|
| Текст/документація | diff, коректність посилань і даних |
| Перенесення файлів | карта перенесень, SHA-256 до/після, залежності, git status |
| CSS/блок | desktop + 390px/360px; зразок на тій самій ширині; переповнення, кольори, відступи, шрифти |
| Інтерактивний блок | потрібні hover/focus/open/close, клавіатура та найдовший контент |
| JS/форма | сценарій, який змінено, помилки; без зайвих реальних відправлень |
| Нова/суттєво перероблена сторінка | огляд від hero до footer, SEO-чекліст, mobile Lighthouse |

- Для кнопок перевіряти не лише фон: текст, колір, розмір, padding, border, іконку, hover/focus і анімацію.
- Для FAQ перевірити закритий та відкритий стан, найдовшу відповідь і відсутність обрізання на мобільному.
- Для анімацій перевіряти початковий і кінцевий стан; текст не повинен залишатися прихованим при збої.
- Lighthouse не потрібний після дрібної CSS-правки чи документації. Для готової нової/значно переробленої сторінки потрібний; якщо недоступний — чесно вказати, що перевірка не завершена.
- Старі оцінки Lighthouse не копіювати як поточні. Відокремлювати проблеми коду від сторонніх скриптів.
- Не повторювати успішні перевірки без зміни коду чи нової причини.
- Відсутність конкретного інструмента не забороняє еквівалентну перевірку доступним способом; не заявляти, що вона пройдена, якщо це не так.
