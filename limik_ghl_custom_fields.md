# Поля для настройки в GHL

Сайт передаёт данные через вебхук `J26g7N7tbNqN9LDOAD1K` при отправке любой формы.
Ниже — все поля по каждой форме, в том порядке, в котором они реально уходят.

`firstName`, `lastName`, `companyName`, `email`, `phone` — стандартные поля контакта в GHL, маппятся сами.
Всё остальное нужно создать как **Custom Fields** и связать в workflow вебхука с названием поля из колонки "Поле в запросе".

## 3. Первое касание (first-touch) — новые поля, одинаковые на обеих формах

Отдельно от полей выше (которые всегда отражают **текущую** заявку), сайт теперь дополнительно передаёт **first-touch**-версии тех же меток — значение первого визита с рекламы, зафиксированное в браузере пользователя и хранящееся 90 дней (после этого срока фиксируется заново при следующем визите с UTM/gclid).

Логика: `utm_source` и `first_utm_source` могут отличаться, если человек кликнул по одному объявлению, а заявку отправил через несколько дней уже после клика по другому объявлению (или зашёл напрямую) — `utm_source` покажет последний источник, `first_utm_source` — самый первый.

| № | Поле в запросе | Что это |
|---|---|---|
| 1 | `first_utm_source` | Первый источник рекламы (не текущий) |
| 2 | `first_utm_medium` | Первый канал рекламы |
| 3 | `first_utm_campaign` | Первая кампания |
| 4 | `first_utm_term` | Первое ключевое слово |
| 5 | `first_utm_content` | Первый вариант объявления |
| 6 | `first_gclid` | ID первого клика Google Ads |
| 7 | `first_fbclid` | ID первого клика Facebook Ads |
| 8 | `first_ga_client_id` | GA4 Client ID при первом визите |

Важно: эти поля приходят в запросе **только если** для них есть сохранённое значение (т.е. человек хотя бы раз заходил с рекламной ссылкой за последние 90 дней). Если человек всегда заходил напрямую — этих полей в запросе не будет вообще, как и обычных `utm_*`.

---

## Что нужно сделать в GHL

1. Создать кастомные поля контакта под все пункты из колонки "Поле в запросе" (кроме `firstName`, `lastName`, `companyName`, `email`, `phone` — они стандартные).
2. Поля с одинаковым названием (`message`, `formSource`, `pageUrl`, `utm_*`, `gclid`, `fbclid`, `ga_client_id`, `first_*`) — общие для обеих форм, создавать один раз.
3. В workflow вебхука замаппить каждое поле из тела запроса на созданное кастомное поле контакта.
4. Поле `ga_client_id` — уже настроено и проверено (2026-07-03).
5. Поля `first_*` (раздел 3) — новые, нужно создать и замаппить. **Обязательно проверить в workflow, что маппинг first_-полей не перезаписывает существующие данные контакта** — если у контакта уже есть значение в `first_gclid` от прошлой заявки, повторная заявка не должна его стирать (сайт со своей стороны это уже гарантирует — присылает первое значение за 90 дней, а не текущее).
